# TaskFlow: будущий пульт внутри чата

Статическая спецификация следующего релиза. Открыть [макеты](mockups.html) в браузере: слева светлая тема, справа тёмная; ниже — список, карточка и состояния. Файлы работают локально, без сервера, сети, шрифтов и JavaScript. Все имена и значения вымышлены. Кнопки на макетах не выполняют действий.

В текущем релизе `TELEGRAM_HTML_WIDGET_ENABLED=false`. Пользователь работает через обычные Telegram HTML-сообщения и inline-кнопки; значение `true` отклоняется при проверке конфигурации. Эти макеты не являются Telegram HTML-сообщениями, реализацией Widget API или Rich Messages. Они не загружаются приложением и не отправляются пользователю. Пульт не открывает отдельное приложение.

Снимки: [обзор двух тем](overview.png), [ширина 320 px](mobile.png). [Результаты проверки](VALIDATION.md).

## Состав и границы

| Макет | Что проверять |
| --- | --- |
| Обзор недели | Два участника, баллы и цель, входящие оценки, основные разделы |
| Список задач | Ровно пять задач, фильтры, статусы, длинное название, следующая страница |
| Карточка общей задачи | Автор, исполнители, оценка, срок, комментарий, доступные действия |
| Подтверждение | Явное начисление обоим, безопасный возврат, отсутствие ранней мутации |
| Состояния | Пустой список, ошибка, загрузка, устаревшая карточка |

Новая версия пульта должна повторно пройти проверку совместимости официального Widget API с aiogram, Telegram iOS/Android/Desktop и действующими контрактами callback. Наличие CSS в этих макетах не доказывает его поддержку в Telegram. Финальный транспорт, разрешённый HTML/CSS, ограничения размеров и доступность определяются проверенной документацией API и тестированием клиентов; этот файл не утверждает их наличие.

## Сценарии и контракты

1. `/start` и `/menu` открывают актуальный обзор в переписке. `/menu` прерывает форму по действующему правилу; переход из другой старой карточки во время формы требует существующее подтверждение потери черновика. Навигация не отправляет пользователя по URL.
2. Обзор показывает явный диапазон понедельник—понедельник и общую `DEFAULT_TIMEZONE`. Две строки участников имеют одинаковый визуальный вес. Баллы берутся из неизменяемых score events за эту неделю. Цель показана рядом; превышение цели не обрезает число. Прогресс ограничен 100% только визуально, числовое значение сохраняется.
3. «Входящие · N» открывает оценки только текущего оценщика. Оценка требует подтверждения и актуальной версии. Одно входящее событие не создаёт отдельный пульт на каждую задачу: действующие debounce, outbox и часовой cooldown сохраняются.
4. «Мои задачи» показывает не более пяти задач на странице. Фильтр и страница сохраняются при возврате из карточки. Крайние кнопки пагинации отсутствуют или недоступны. Поиск и фильтры, если их поддерживает текущий чат, остаются в переписке.
5. Названия не передают смысл цветом и не становятся иконками. В списке название переносится, без горизонтальной прокрутки; карточка показывает его полностью. В непрерывных строках разрешён перенос. Динамический текст экранируется перед рендерингом; HTML из названия или комментария не исполняется.
6. Карточка показывает роли отдельно: кто предложил, кто выполняет, кто оценивает. Для общей задачи явно указаны два исполнителя и полная цена каждому. Статус один для обоих; завершение и отмена начислений атомарны в сервисах.
7. Доступность действий вычисляет сервер по текущему состоянию и роли. Ручной BACKLOG ожидает второго участника; шаблоны SELF/SHARED заранее оценены и создают TODO, PEER следует существующему согласованию. TODO → IN_PROGRESS/DONE, IN_PROGRESS → TODO/DONE. CANCELLED терминален. На макете показан допустимый набор действий одной общей TODO-задачи; это не универсальная клавиатура.
8. Удаление/отмена задачи, выход из DONE, изменение цены требуют существующих подтверждений. Для отмены и выхода из DONE показывать конкретный эффект на баллы; выход из DONE компенсирует исходные начисления в исходной неделе. Завершение может показывать существующий быстрый переход; дополнительное подтверждение на макете — вариант будущего пульта, не требование изменить текущий сервис.
9. Изменение названия/усилий сбрасывает согласование; срока/комментария — нет. Цена доступна только текущему ручному оценщику в TODO/IN_PROGRESS с подтверждением. Редактирование принятой личной задачи контролирует исполнитель. Форма создания/редактирования остаётся пошаговой, с Назад, Пропустить и пресетами; будущий пульт не меняет бизнес-правила.
10. «Из шаблона», штрафы, типы штрафов и настройки ведут в существующие чатовые сценарии. Для штрафа подтверждение показывает сохранённый расчёт; изменившийся preview отклоняется. Пульт не рассчитывает историю из текущих цен.
11. Любое действие проверяет ENV-пользователя и соответствующий личный чат. Payload содержит существующий идентификатор, версию/flow и operation key по контракту сценария. Повторное нажатие не создаёт второго события. Нельзя доверять скрытой/disabled кнопке вместо серверной проверки. Бизнес-логика остаётся в services; транзакцией управляет вызывающий код.
12. После успеха обновить ту же карточку и кратко сообщить результат. При неизвестном результате отправки не повторять мутацию/доставку вслепую. При устаревании предложить «Обновить карточку», не воспроизводить прежнее действие. Недоступная задача возвращает понятный ответ и путь к списку без раскрытия чужих данных.

## Визуальная система

Системный шрифт без скачивания, основной кегль 16 px, подписи 14 px, интерлиньяж 1.45. Сетка 4/8 px, отступ карточки 16 px, промежуток 8–16 px. Радиусы 12–16 px. Минимальная цель нажатия — 44 × 44 px. Цвет статуса дополняет текст; баллы имеют единицу «★». Спокойный синий выделяет действие, зелёный — результат, красный зарезервирован для опасного действия/ошибки.

Макеты показывают мобильную ширину 360 px и сжимаются до 280 px (эквивалент узкого содержимого при масштабировании). На широком экране колонки сравнивают темы, а не задают рабочий desktop layout. Внутри реального чата — одна колонка. Нет закреплённых панелей, перекрывающих длинный текст. Официальная тема клиента должна задавать итоговые токены только через документированный механизм.

## Доступность и состояния

- Семантические заголовки, списки, нативные кнопки, текстовые названия. Иконки декоративны. Порядок чтения совпадает с визуальным. Фокус заметен; нет hover-only действий, жестов и положительного tabindex.
- Основной и вторичный текст: контраст не менее 4.5:1; границы интерактивных элементов и фокус — 3:1. Предлагаемые токены в CSS проверены расчётом контраста. Финальная проверка включает реальные темы Telegram.
- Числа прогресса доступны текстом, индикатор имеет доступное имя. Нельзя объявлять каждое обновление счётчика; после действия — один `status`, ошибка — `alert`, если платформа поддерживает соответствующую семантику.
- Пустой список объясняет активный фильтр и даёт создание задачи/сброс фильтра. Ноль входящих — «Все предложения оценены», а не ошибка.
- Загрузка сохраняет структуру и текст «Загружаем задачи…», не сообщает фиктивные нули. Никакой обязательной анимации; reduced motion не меняет функциональность.
- Ошибка сохраняет контекст и предлагает повторить чтение. Кнопка повтора мутации появляется только при определённом результате и действующей идемпотентности. «Назад» доступно всегда.
- Подтверждение содержит название действия и сумму последствий; фокус ставится на заголовок/безопасное действие, возвращается к источнику при отмене. Отдельная карточка в переписке предпочтительнее вложенного модального окна.

## Проверка до отдельного релиза Widgets

Проверить светлую/тёмную темы, 320/360/430 px и масштаб 200%, длинные кириллические и непрерывные названия, крупные суммы, пустые/ошибочные данные. Пройти клавиатурой, VoiceOver и TalkBack. Проверить чтение статусов и порядок фокуса после обновления. Автотест контраста/переполнения не заменяет проверку assistive technology.

Сценарии приёмки: личная и общая задача; все три вида шаблонов; страницы 0/1/последняя; входящие без прав и устаревшая оценка; двойное завершение; отмена/выход из DONE с компенсацией исходной недели; редактирование цены; изменившийся preview штрафа; прерывание форм; уведомление со старой версией; отсутствие сети; недоступное старое сообщение. Проверить, что во всём сценарии пользователь остаётся в чате.

Для текущего релиза отдельно проверить отсутствие Widget API и `sendRichMessage` при выключенном флаге и отказ запуска при `true`. Живой Telegram-клиент, поведение будущего Widget API и его доступность этими статическими файлами не проверены.
